the attack to happen**. Written 2026-09-18 from a code read; re-evaluated
2026-09-24 (four read-only reviews: tiers 0–1, tier 2, tiers 3–4,

was not a new full audit of every row. On 2026-10-04 four read-only reviews
checked the code since then (`e5ad85b5..149ba21b` plus the uncommitted
markup tick): agent API keys and the API proxy, the phone surface, the MCP

perimeter/viewers/mail/supply chain) re-checked every row in their areas
against `21eadf64` and cross-reviewed at `ff9f83ab`: no fixed gap regressed;

Each "✅" names the defence
that holds it. Verify against code before relying on a row — this file is a
map, not a proof. Open items are tracked in `todo/group-o-security.md` (#146,
#151, #158, #160, #861–#870, #2342–#2349, #2424–#2426); turning each "yours" row into a safe default is
planned in `docs/safe_for_everyone_plan.md` (#2321–#2333, not started).

**Legend** — ✅ defended · ⚠️ residual (known, bounded, or needs your care) ·
❌ open gap · 🔍 not audited.

**Who is responsible.** Tiers 0–2 are Tabtivity's job: nothing you receive or
merely look at should ever run code. Tier 3 is shared: Tabtivity contains the
agent, but the agent's power is the permission mode *you* gave its CLI. Tier 4
is yours: running something is running something, same as in any terminal.

## The one fact everything hangs on

The main window's IPC reaches the whole backend — terminals, git, mail send —
through about 760 registered `#[tauri::command]`s (2026-11-04: 588 `core`, 100 `client`, 67 `admin`, 9 `off`) (`generate_handler!` in
`lib.rs`) with no per-command ACL. The same holds for
every `main`, `detached-*` and `present-*` webview. Tauri checks app commands
only for remote origins, so **any script running in one of those webviews is
full compromise.** Three layers stop that: every renderer is escape-first (no
raw document HTML reaches the DOM); the CSP (`script-src 'self' blob:`, no
`unsafe-inline`, no `unsafe-eval`, guarded by `tests/capability_scope.rs` and
`CspTripwire.test.ts`) blocks inline handlers and `eval` even if one renderer
slipped; and `Object.prototype` is frozen before bootstrap
(`lib/hardenPrototype.ts`, #159). Browsed pages live in separate `browser-*`
webviews whose capability grants nothing (`src-tauri/capabilities/browser.json`).
Plugins are dialog, drag and notification only — no shell, fs, http, opener or
updater plugin, no asset protocol, `withGlobalTauri` off. The desktop CSP also
carries `object-src 'none'; base-uri 'none'; form-action 'none'` (gap 62, in the shipped config since
2026-10-24; `script-src blob:` stays for the pdf.js worker). The patched
`src-tauri/patches/tauri-runtime-wry` differs from upstream 2.12.1 only by the
documented `TABTIVITY PATCH` hunks (diffed 2026-10-24; no change to
`src-tauri/patches/`, the capabilities or `hardenPrototype.ts` through `b3abe5ba`).
The microphone is declared on macOS (`NSMicrophoneUsageDescription`, entitlement
`device.audio-input`) for the Chat's native dictation, which runs in the Rust
process (`services::voice`, cpal), not the webview. A browsed page is kept off it
by the app-level `on_permission_request` deny-all (`with_macos_permission_deny`,
asserted by `capability_scope.rs`, because wry's macOS delegate grants media
capture when no handler is set); Linux keeps WebKitGTK's default deny, Windows the
`commands::browser` deny handler.

**On Linux the WebKitGTK web process of every app window runs without WebKit's own
sandbox** (wry 0.57 never enables it on the GTK3 API), so a WebKit memory-safety bug
reached by content an app window renders — PDF fonts (mitigated by `disableFontFace`),
images, SVG, media, the HTML preview, including pictures and PDFs an agent reply
names — is code execution as the user with the IPC bridge in reach and no second
escape needed. Gap 51: mitigated, not fixed; the sandboxed `webkitgtk-6.0` route is
tracked (`docs/browser_plan_b.md`).

The phone PWA is a second origin: script there equals a paired device. Its
bridge serves `script-src 'self'; object-src 'none'; base-uri 'none';
frame-ancestors 'none'`, `img-src 'self' data: blob:` (library covers are object
URLs; images only, no script), `nosniff`, `DENY` on ordinary responses. The sealed
PDF frame is the deliberate framing exception: its separate CSP allows only
the phone origin to frame it.

**The browser desktop client (`/desktop/`, Settings → Mobile → Browser access) is a
third origin.** Script there can call every `core` command and, on the desktop
sidecar, `admin` commands too, since every web session runs as `Role::Admin`: it is
equal to a paired device with the whole desktop behind it. Its page CSP is
`script-src 'self' blob:` plus inline-script hashes and `style-src 'unsafe-inline'`;
its row is in tier 0.

## Server mode (hosted)

The hosted version runs the same core in a per-user daemon behind a gateway
(`docs/server.md` is the front door; the plan's threat rows are in
`docs/tabtivity_hosted_plan.md` § 4.4). Per `docs/server.md` it has never run on a
real server, so nothing below is live-verified. The 2026-10-24 recheck only spot-checked
it: `core_dispatch` `USER_CONFINED` rows were not read one by one, and the hub,
calendar service, key keeper, key broker and OIDC internals were not re-read.

| Piece | What an attacker gets | Defence | Status |
|---|---|---|---|
| **The uid boundary** (per-user daemon `<slug>-serverd@<user>`, own tmux, `0700` home) | Another account can do whatever its own uid can, an unfenced shell included. | The uid is the boundary: the gateway routes a request only to its caller's own daemon, whose socket (`/run/<slug>/users/<user>.sock`) only the gateway's uid may connect to (peer-uid check). The daemon is its user's, not Tabtivity's: what it tells the gateway, helper, hub or keeper (presence, share requests, credential files) is untrusted and attributed by peer uid; gateway routing headers are trusted only from the socket peer. Anything world-readable on the host stays readable. | ⚠️ by design; `scripts/server-isolation-test.sh` still owed (not verified) |
| **`core_dispatch` confinement** | A `Role::User` web or Connect client naming paths | `USER_CONFINED` holds every path-named argument of every `core` command to the user's roots before the body runs (`6e8ae492`, `30c02942`). It is defence in depth behind the uid, not the boundary: the daemon runs as the user, and an unfenced shell tab is a feature. | ⚠️ defence in depth |
| **Client ssh logins** (decision `a41799cc`, 2026-10-15) | A non-admin client adds a host and logs in to it | The "approve client ssh hosts" gate of `f664c6e9` was dropped: a non-admin client exists only on a per-user daemon, which has no desktop window and which the admin's browser never reaches, so nobody could approve — and the account already has unfenced shell tabs. Kept: a client's ssh login still needs a stored host, and its argv is built from the stored user, host and port, never the caller's spelling. | ⚠️ decision |
| **Shared Ollama** (`127.0.0.1:11434`, the admin's service) | Every account's shell can reach it directly. | Only the admin pulls, deletes, loads, stops or starts models; users get only the models the admin allowed, checked on every server request path. A listener on that port is trusted only when owned by root, a system account or the uid the administrator names in the server policy file (`ollama_listener_uid`); the daemon's own uid is a tenant (gap 50, Linux only, fixed, not live-verified). **Residual:** direct requests from any shell to the shared service are model use, not admin; no UI sets the policy key. | ⚠️ |
| **Browser client and fetches** | A client's reader or calendar URL; its pasted markdown | A client's reader/ICS hop 0 is judged like a document's — it may not aim the server at its own network — and no fetch for a client uses a proxy (gap 63); a server on a proxy-only network loads no remote markdown images (`docs/guide/server.md`). | **Deferred** | — | #2353 (a gateway body cap and the rest of the gateway/helper security review), #2358, #2372, #2379, #2384 (`docs/server.md` § Open problems). Not re-read: the hub, calendar service, key keeper, key broker and OIDC internals.

## Out of scope

Malware already running as your user (it can read `~/.config`, drive tmux,
and inject into any process you own), a compromised OS or WebKitGTK (but see the
unsandboxed Linux renderer, gap 51), physical access to an unlocked machine. Other local *users* are **in** scope (gap 4,
state-dir permissions).

## Hardening backlog (not vulnerabilities today)

- `Object.prototype` is frozen in Tabtivity's own windows (#159, done
  2026-09-18) by `lib/hardenPrototype.ts`, not Tauri's `freezePrototype`: that
  flag also freezes browsed pages, and a bare freeze breaks pdf-lib (the
  "override mistake"). The phone PWA is not hardened this way.
- `mobile_control` mutex locks recover from poisoning (done 2026-09-18), so a
  panicking handler can't lock the phone out.
- #869 batch: `object-src 'none'; base-uri 'none'; form-action 'none'` were added to the
  desktop CSP 2026-10-24 (gap 62, shipped); `script-src blob:` stays for the pdf.js
  worker; forward agent API keys only to agent
  tabs (the app's ambient env keys; keys saved in Manage CLIs already reach
  local agent tabs only). Done 2026-09-24: the state dir is tightened to 0700 at startup
  (`storage::ensure_private_state_dir`) and new state files are written 0600
  (`storage::write_json`; project-folder files keep the umask); every
  workflow action is pinned by commit SHA.
- `cargo audit` ignores RUSTSEC-2023-0071 (`rsa` timing, via `pgp`) and RUSTSEC-2026-0367,
  -0368 and -0369 (`zip` 8.6 via `calamine`). 2026-11-04: `Cargo.lock` now holds only `zip`
  9.0.5 (calamine 0.38), so the three zip ignores are obsolete and should go before they
  mask a future 8.x; RUSTSEC-2026-0387 (`crypto-bigint` 0.5.5 timing, via `p256` for phone
  pairing and `pgp` 0.20 for mail) is new and waits on the `pgp` 0.21 / `p256` 0.14
  generation. New native crates: `whisper-rs` (pinned `=`, cmake + bindgen, no network at
  build), `cpal`, `tts` (non-Linux); the package jobs download the LunarG Vulkan SDK and
  the Windows Vulkan runtime, each pinned by sha256 in `ci-cd.yml`, and the bundles link
  the system Vulkan loader. Dependabot runs weekly with a 7-day cooldown and Tauri/wry pinned out;
  the release job runs from `workflow_run`, gated to a push on `main` of this repo.
- Landlock TCP-bind restriction for the agent fence (kernel ≥ 6.7; gap 50, D7) and the
  sandboxed `webkitgtk-6.0` renderer (gap 51, D8) are tracked, not built.
- Mail search (`mail_engine::imap_quoted`) drops CR/LF but keeps NUL, which
  `mail_move` refuses for mailbox names. The query is typed by the user and a
  NUL only makes the server answer `BAD`; strip it there too for symmetry.
- A re-import of an OpenPGP key keeps its trust flag but replaces its user IDs
  (`PgpKeyring::import`). Self-signatures stop a third party adding a user ID, but
  anyone with a verified correspondent's public key can send it back with user
  IDs dropped or reordered. (The key's *owner* can add user IDs: that half is
  gap 76, not hardening.) That changes which address `good_outcome` takes
  (`addresses.first()`), so that person's real mail can show as Unaligned.
  Nothing can be forged this way. Match on every address of the key, not
  only the first.
