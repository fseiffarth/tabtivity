# ProjectEldrun — Backend File Map (`src-tauri/src/`)

See the root `AGENTS.md` for project rules; `docs/filemap_frontend.md` is the
frontend file map.

Deliberately **not** a `CLAUDE.md` (agents auto-load those). Grep it for the
file you touch. **One line per row**: what the file is for, plus an invariant
only when breaking it does damage. The *why* goes in code comments or
`docs/context/`, never here. Pre-2026-09-18 long-form rows: `docs/filemap_rationale/backend.md`.

**Top level**

| File | Purpose |
|------|---------|
| `main.rs` | Tauri app entry point, plugin registration. |
| `lib.rs` | Command registration (`generate_handler!`), app setup, hook/restore install; crash logger (panic hook + async-signal-safe fatal-signal handler that restores `SIG_DFL` and re-raises; headers carry `commit=` so `scripts/crash-symbolize.sh` can use the build `scripts/retain-dev-build.sh` kept); per-window renderer reload budget; macOS menu bar (`macos_menu_plan`). |
| `storage.rs` | JSON persistence helpers: unique-temp atomic replacement (staged file fsync → rename → parent-directory fsync, #172, observed by tests through the `durability` seam) and serialized, corruption-preserving read-modify-write transactions. `FileLock`: the advisory sibling-`.lock` guard that serialises a second Tabtivity process; `patch_json` holds it across its read-modify-write. |
| `paths.rs` | Canonical Tabtivity directory paths. |
| `brand.rs` | The app's name: the one backend place it is spelled. Display/slug/upper forms, literal macros for `concat!` (`app_name!`, `app_slug!`, `app_env!`, `app_tab_command!`), and every name the app persists or puts on the wire as a current constant plus its `LEGACY_*` twin (old brand). `build.rs` includes it by path. Twin of `src/lib/brand.ts`. The dev scripts read the same names through the sourced `scripts/lib/brand.sh` (parses this file and `Cargo.toml`'s `[[bin]]`; a test here sources it and compares). |
| `sysstat.rs` | Per-process CPU via `/proc` (`descendant_pids`), whole-system `SystemSnapshot`, and `machine_load()` — aggregate-only, no process table (cheap enough to poll). Unsupported target answers `supported: false`, never zeros. |
| `gpustat.rs` | Whole-device GPU memory as two pools (dedicated VRAM + shared/GTT; callers sum) plus sensors, from DRM sysfs or `nvidia-smi`; ~1 s cache. Missing readings are `None`, never 0. Per-process GPU is separate (monitor only). Remote hosts parsed by the same parsers. |
| `../patches/tauri-runtime-wry/` | Vendored tauri-runtime-wry 2.11.3 via root `[patch.crates-io]`; one `TABTIVITY PATCH` (`Context.main_thread` behind an `Arc`) stops off-thread `AppHandle` clones racing tao's Linux `Rc` — re-apply on every tauri bump. |

**Services (`services/`)** — `AppHandle`-free, unit-testable.

| File | Purpose |
|------|---------|
| `text_completion.rs` | AppHandle-free completion reservations/cancellation and bounded NDJSON transport; abort drops the HTTP socket, with Unicode/chunk/cancellation tests. |
| `ssh_common.rs` | Shared SSH argv + validation helpers (`validate_arg`, `ssh_*_base_args`, `ssh_target`, `sshpass_available`). |
| `mobile_control/` | AppHandle-free Tabtivity Mobile sidecar core: loopback HTTP/PWA server, exact-origin device auth, bounded admin/desktop protocols, audit store, tmux PTY/WebSocket bridge. Raw project ids, paths, commands, tmux targets never cross the browser API; phone-facing schedule and prompt response types omit stored prefix commands, session ids and target ids. `/api/v1/status` reads the desktop's `show_untested_tags` display preference for the phone. Per-device `hidden_sections` (`auth::HIDEABLE_SECTIONS` todo/calendar/mail, in `devices.json`, set by admin `set_hidden_sections`): `host::section_guard` answers 403 `section_hidden` on that section's routes, `open_alerts` drops its alert rows (a ✓ on one is refused), a phone without calendar gets no calendar push, and `/api/v1/status` names them for the phone's tab bar. The phone writes tab labels, colours, order, close/create, schedules and prompts through the desktop bridge. Sessions live in memory only (sliding `auth::SESSION_IDLE`); every socket carries `limits::IDLE_TIMEOUT`; `pty_bridge` acks each input frame (`TerminalEvent::Ack`), replays history in ≤64 KB frames and, under flood, blocks its PTY reader so tmux discards and redraws (never drops bytes itself). Per-phone access (`docs/context/mobile_access.md`): a scope's `tabtivity_mobile_devices` list is read leniently and `Catalog::for_device` filters every phone route through `host.rs`'s `Phone`; push goes only to the listed phones. `discovery.rs`: scopes are projects, boxes and — behind `root_open`'s switch + review gate — the root console (`docs/context/root_console.md`). `files.rs`: read-only project tree for the phone's 📁 (#31bo) — folders and files named by sealed tokens (XChaCha20-Poly1305 under `HKDF(host.key)`, AAD = raw project id), every request re-proves root + relative path with no link on the way; behind `tabtivity_mobile_host.project_files` (read per request, default off), projects only; bytes typed as `outbox.rs` does (`sniff_opened`); its `ProjectDir` (held-folder walk, `lookup_dir`/`create_dir`/`create_file`/`remove_file`) is also the drop boxes' only way in — `outbox::drop_dir` and `inbox` never open a drop-box path (gap 12); `search` (`GET …/files/search?q=`) matches leaf names over `git ls-files -co --exclude-standard` (bounded walk outside a repo), each hit re-proven like `entry` and answered with its sealed folder trail. `git_overview.rs`: `GET /api/v1/projects/{id}/git`, sidecar-answered with or without a window: worktrees (opaque ids = the ＋ sheet's), branches, remote branches, per-worktree dots; hardened reads, 8 probes / 3 s budget, 5 s cache; projects only. `inbox.rs`: project inbox (`.tabtivity/inbox/`) and the global one (`<state_dir>/inbox/`, `POST /api/v1/inbox`, listed/opened/deleted by leaf via `global_inbox_*`); the project inbox reads back to the phone only by the leaves it names (`describe`/`read`, `GET …/tabs/{id}/inbox?names=` and `…/inbox/{leaf}`, probed as `outbox.rs` probes). `push.rs`: Web Push to subscribed phones (VAPID + RFC 8291 `aes128gcm`, push-vendor host allowlist, no redirects), held inside `AuthStore` so revoke drops a subscription; per-phone choices (calendar / agents off·questions·all / details), per-tab 30 s cooldown. Fed by admin `notify` (desktop reminder engine) and `agent_turn` (desktop edge → `host::agent_tab_ref`, silent while a phone holds the tab). `sign_in.rs`: relays a phone-pasted OAuth `http://localhost:<port>/…?state=…&code=…` address to the agent CLI's loopback listener (one GET, no redirects, status only). `markup.rs` + `markup_pdf.rs`: the phone's Mark up Submit (`POST /api/v1/tabs/{id}/markup`, 4 MiB) — validates the vector marks and inbox layer refs, reads the source (sealed files token of the tab's project, or outbox leaf) read-only, bakes `<stem>-marked.pdf` into the inbox as an incremental update with `/Ink`/`/Highlight`/`/FreeText` + appearance streams (own bounded PDF reader: classic/stream/hybrid xref, object streams, page-tree inheritance, `/Rotate`; encrypted refused; step budget + deadline + `catch_unwind`), answers the chat prompt (its closing instruction is the phone's setting, else `DEFAULT_INSTRUCTION`: list, edit nothing until told; page list + one line per mark capped so the prompt stays ≤ `MAX_PROMPT_BYTES` 12 KB). Pages arrive `composed` (the page with its marks drawn on, `-p<n>-marked.png`) or as marks alone, with per-mark `anchors` (the page's words, `How`: through/under/around/at/on/beside); for a project PDF with a current SyncTeX map each mark gets its project-relative `file:line` (`source_lines`, ≤ 400 lookups); with all pages composed the marked copy is named without `@`; `validate` = `validate_source` + `validate_body`; `submit_local` is the desktop's entry (`commands::pdf_markup`); `/pdf-frame.html` is the one framable page (`SAMEORIGIN`, no-network CSP). `headless.rs` (headless owner plan, H0): when the desktop socket reports no window, `host.rs` answers the to-do board, a calendar month, a tab's schedules, a project's prompts and an agent transcript off the state dir — same opaque ids (`host.key`), read-only, flagged `desktop_available: false`. H1b: with no window it also answers the catalog's agent list (installed resumable built-ins, `disabled_agents` honoured), each agent tab's status/model/prompts/schedule summary (the hooks' `live_sessions/*.turn` records + the tab's transcript, cached `READING_TTL`), the project list's git dots (`git_dot_for`, hardened probes off-thread, cached) and `Create` for a shell or plain agent: `workspace::create_tab_in` (owner-minted id, tmux name, schedule binding, idempotent on the request hash) then the host's spawn seam `HeadlessSpawner` (`launch_prep::prepare` + `tmux_local::spawn_detached_with` on the default tmux server; a test records the `PtyOptions`); a failed launch takes the record back out. A sign-in, cloud, worktree, local-model, mode or root-console create still needs the window. `scheduler.rs` (H2): the owner's scheduled-prompt loop, a 15 s tick in `host::run` — while no window holds `timer_lease`, every bound agent tab's due rule is claimed (`agent_tasks::claim_in`, cross-process), typed into its tmux session (`send-keys C-a C-k`, `load-buffer` + `paste-buffer -r [-p]`, `Enter`; prefix commands first, each settled), completed and written to the prompt history; idle = the hooks' `.turn` record (working/decision/idle hold, `done` after 3 s) plus the session's `window_activity` quiet (2 s; 30 s with no record); a tab whose session is gone is restarted through the launch seam (60 s backoff) and delivered to on a later tick; occurrences past the hour are recorded missed.
