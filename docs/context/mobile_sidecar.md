# Mobile sidecar — module notes (`src-tauri/src/services/mobile_control/`)

Per-file detail of the phone sidecar core. Who may reach a scope:
`mobile_access.md`. The file map keeps one line for the folder.

Moved verbatim from the file map on 2026-10-19; verify against the code.

AppHandle-free Tabtivity Mobile sidecar core: loopback HTTP/PWA server, exact-origin device auth, bounded admin/desktop protocols, audit store, tmux PTY/WebSocket bridge. Raw project ids, paths, commands, tmux targets never cross the browser API; the project detail's `terminals` (`discovery::terminals_support`: `tmux`, or `unsupported` on Windows, the predicate `live_tmux` short-circuits on) tells the phone to hide ＋, Schedule and Mark up's Submit; phone-facing schedule and prompt response types omit stored prefix commands, session ids and target ids. `/api/v1/status` reads the desktop's `show_untested_tags` display preference for the phone. Per-device `hidden_sections` (`auth::HIDEABLE_SECTIONS` todo/calendar/mail, in `devices.json`, set by admin `set_hidden_sections`): `host::section_guard` answers 403 `section_hidden` on that section's routes, `open_alerts` drops its alert rows (a ✓ on one is refused), a phone without calendar gets no calendar push, and `/api/v1/status` names them for the phone's tab bar. The phone writes tab labels, colours, order, close/create, schedules and prompts through the desktop bridge. `POST /api/v1/projects` makes a phone's new project by name only, with or without a window (`commands::projects::create_project_for_phone`: `<projects root>/<folder>`, active, open to that phone alone; seam `HeadlessSpawner::new_project`). Sessions live in memory only (sliding `auth::SESSION_IDLE`); every socket carries `limits::IDLE_TIMEOUT`; `pty_bridge` acks each input frame (`TerminalEvent::Ack`), replays history in ≤64 KB frames and, under flood, blocks its PTY reader so tmux discards and redraws (never drops bytes itself). Per-phone access (`docs/context/mobile_access.md`): a scope's `tabtivity_mobile_devices` list is read leniently and `Catalog::for_device` filters every phone route through `host.rs`'s `Phone`; push goes only to the listed phones.

`discovery.rs`: scopes are projects, boxes and — behind `root_open`'s switch + review gate — the root console (`docs/context/root_console.md`).

`files.rs`: read-only project tree for the phone's 📁 (#31bo; its one write is `uploads.rs`) — folders and files named by sealed tokens (XChaCha20-Poly1305 under `HKDF(host.key)`, AAD = raw project id), every request re-proves root + relative path with no link on the way; behind `tabtivity_mobile_host.project_files` (read per request, default off), projects only; folder rows carry `items` (valid children through the same handle walk, capped at `MAX_ENTRIES + 1`, under a 20 000-name `ITEM_SCAN_BUDGET` per listing, left out when not counted); bytes typed as `outbox.rs` does (`sniff_opened`); its `ProjectDir` (held-folder walk, `lookup_dir`/`create_dir`/`create_file`/`remove_file`) is also the drop boxes' only way in — `outbox::drop_dir` and `inbox` never open a drop-box path (gap 12); `search` (`GET …/files/search?q=`) matches leaf names over `git ls-files -co --exclude-standard` (bounded walk outside a repo), each hit re-proven like `entry` and answered with its sealed folder trail.

`uploads.rs` (`docs/done/phone_upload_plan.md`): **Upload here**, `POST`/`DELETE …/files/upload` — behind `tabtivity_mobile_host.project_uploads` (default off, only with `project_files`; `uploads_open`), add-only into an existing folder named by a sealed token, no dot segment (`accepts`, also the listing's `uploads` flag), `inbox::create_unique` (the inbox's `O_EXCL` `-2`/`-3` loop, shared) under the inbox's `safe_name` without a stamp, 24 MiB a file, 1 GiB per project per 24 h; one JSON line per landed file in `<state_dir>/mobile-control/phone-uploads.jsonl` (sidecar is its only writer; 7 days, compacted under `LOG_LOCK`); `undo` deletes only a logged file still intact (regular, no link, same size + sha256), `recent` (hash cache keyed by record + root) feeds the desktop's `phone_uploads_list`.

`git_overview.rs`: `GET /api/v1/projects/{id}/git`, sidecar-answered with or without a window: worktrees (opaque ids = the ＋ sheet's), branches, remote branches, per-worktree dots; hardened reads, 8 probes / 3 s budget, 5 s cache; projects only.

`inbox.rs`: project inbox (`.tabtivity/inbox/`) and the global one (`<state_dir>/inbox/`, `POST /api/v1/inbox`, listed/opened/deleted by leaf via `global_inbox_*`); `safe_name` suffixes a Windows device name `_` on every OS; the project inbox reads back to the phone only by the leaves it names (`describe`/`read`, `GET …/tabs/{id}/inbox?names=` and `…/inbox/{leaf}`, probed as `outbox.rs` probes).

`push.rs`: Web Push to subscribed phones (VAPID + RFC 8291 `aes128gcm`, push-vendor host allowlist, no redirects), held inside `AuthStore` so revoke drops a subscription; per-phone choices (calendar / agents off·questions·all / details), per-tab 30 s cooldown. Fed by admin `notify` (desktop reminder engine) and `agent_turn` (desktop edge → `host::agent_tab_ref`, silent while a phone holds the tab). `auth.rs` also redeems the admin helper's server invite (`invite.json` in the control dir, `invite_hash` = SHA-256 over `invite\n`+code, `write_invite`; one enrolment, worn out like a pairing code — the gateway never holds a code). `host::run_with(config, Listen)`: `Loopback` (the sidecar: Tailscale verify, content origin on the next port) or `Unix` (the per-user daemon: `limits::PeerGatedUnixListener` drops every connection not from the gateway's uid at accept, `0660` socket, `/content/*` on the same socket).

`sign_in.rs`: relays a phone-pasted OAuth `http://localhost:<port>/…?state=…&code=…` address to the agent CLI's loopback listener (one GET, no redirects, status only).

`markup.rs` + `markup_pdf.rs`: the phone's Mark up Submit (`POST /api/v1/tabs/{id}/markup`, 4 MiB) — validates the vector marks and inbox layer refs, reads the source (sealed files token of the tab's project, or outbox leaf) read-only, bakes `<stem>-marked.pdf` into the inbox as an incremental update with `/Ink`/`/Highlight`/`/FreeText` + appearance streams (own bounded PDF reader: classic/stream/hybrid xref, object streams, page-tree inheritance, `/Rotate`; encrypted refused; step budget + deadline + `catch_unwind`), answers the chat prompt (its closing instruction is the phone's setting, else `DEFAULT_INSTRUCTION`: list, edit nothing until told; page list + one line per mark capped so the prompt stays ≤ `MAX_PROMPT_BYTES` 12 KB). Pages arrive `composed` (the page with its marks drawn on, `-p<n>-marked.png`) or as marks alone, with per-mark `anchors` (the page's words, `How`: through/under/around/at/on/beside); for a project PDF with a current SyncTeX map each mark gets its project-relative `file:line` (`source_lines`, ≤ 400 lookups); with all pages composed the marked copy is named without `@`; `validate` = `validate_source` + `validate_body`; `submit_local` is the desktop's entry (`commands::pdf_markup`); `/pdf-frame.html` is the one framable page (`SAMEORIGIN`, no-network CSP).

`headless.rs` (headless owner plan, H0): when the desktop socket reports no window, `host.rs` answers the to-do board, a calendar month, a tab's schedules, a project's prompts and an agent transcript off the state dir — same opaque ids (`host.key`), read-only, flagged `desktop_available: false`. H1b: with no window it also answers the catalog's agent list (installed resumable built-ins, `disabled_agents` honoured), each agent tab's status/model/prompts/schedule summary (the hooks' `live_sessions/*.turn` records + the tab's transcript, cached `READING_TTL`), the project list's git dots (`git_dot_for`, hardened probes off-thread, cached) and `Create` for a shell or plain agent: `workspace::create_tab_in` (owner-minted id, tmux name, schedule binding, idempotent on the request hash) then the host's spawn seam `HeadlessSpawner` (`launch_prep::prepare` + `tmux_local::spawn_detached_with` on the default tmux server; a test records the `PtyOptions`); a failed launch takes the record back out. A sign-in, cloud, worktree, local-model, mode or root-console create still needs the window.

`scheduler.rs` (H2): the owner's scheduled-prompt loop, a 15 s tick in `host::run` — while no window holds `timer_lease`, every bound agent tab's due rule is claimed (`agent_tasks::claim_in`, cross-process), typed into its tmux session (`send-keys C-a C-k`, `load-buffer` + `paste-buffer -r [-p]`, `Enter`; prefix commands first, each settled), completed and written to the prompt history; idle = the hooks' `.turn` record (working/decision/idle hold, `done` after 3 s) plus the session's `window_activity` quiet (2 s; 30 s with no record); a tab whose session is gone is restarted through the launch seam (60 s backoff) and delivered to on a later tick; occurrences past the hour are recorded missed. Verdict twin of `scheduleVerdict`.

`alarms.rs` (H2): a 30 s loop that, while no window holds the lease, finds the due calendar reminders (`services::calendar_alarms`), claims them in the shared fired record and pushes each unmuted one to the subscribed phones through `push.rs` (`Notice` kind calendar, title + `HH:MM · place`, tag = the alarm key). `headless.rs` / `headless_board.rs` (H3): with no window the host answers every remaining `DesktopRequest` kind but mail and alerts — tab rename/colour/reorder/close/reopen through `workspace::{rename,color,reorder,close,reopen}_tab_in` (a close ends the session through `scheduler::Runner::kill`, subtree reaped; an agent tab is kept in the file's `workspaceClosedTabs` for a reopen started detached on its resume args), `Activate` (registry status under the lock), `TabPrompt` (`agent_prompts::record_at`), `TabSeen` (a per-uid seen stamp under `mobile-control/seen/`, honoured by the turn readings), `UndoClear` (Claude's `/resume` typed through the runner, Codex relaunched), `ScheduleMutate` / `PromptMutate` (`agent_tasks::upsert_in`, `agent_prompts::{upsert_at,archive_at}`; a send-now is a one-time rule the sidecar's scheduler fires), `TodoMutate` / `CalendarMutate` (`headless_board.rs`: the desktop's board rules over `commands::calendar`'s CAS cores; CalDAV-backed calendars refused), `AgentStatus` (state + today's tally, no usage panel), `LaunchOptions` (folder/shell/agent only), `DesktopImages` / `AttachDesktopImage` (`desktop_images::default_folders`, no clipboard), `HoldPrompt` / `EditHeldPrompt` (a send-now rule marked in `scheduler::PhoneHolds`, typed into the CLI's queue mid-turn unless on a question). Every headless write pokes an open window with `DesktopRequest::Refresh` (fire-and-forget). Mail stays behind the window (store + secrets); alerts too (`buildAlerts` + mutes live in the window); markup questions too (`GET /api/v1/tabs/{id}/markup/questions?source=files:<token>|outbox:<leaf>`, `POST …/markup/answer` 16 KiB / `…/dismiss` → `DesktopRequest::Markup{Questions,Answer,Dismiss}`: the view's source is resolved to its project-relative path before it goes, asks come back with a bare leaf `file_name` — with no source (Focus banner) and the file browser on, the window's `path` is taken out and sealed into a `file_row` (`files::entry`); no window → `desktop_unavailable`, the phone shows no card).

`local_models.rs`: `GET`/`POST /api/v1/local-models` → `DesktopRequest::LocalModels` / `LocalModelMutate` — switch `tabtivity_mobile_host.local_models` read per request (unset = on, 403 `local_models_disabled` before any desktop call), only `load`/`unload`/`start` (anything else 400 `unsupported_action`), the window's list re-sanitized and its refusals allow-listed to fixed codes; **no headless fallback** (no window → 503 `desktop_unavailable`). `host::run` also serves the schedule/git/help MCP lanes for the tabs it spawns (`commands::root_mcp::start_headless`, keyring-free git lane, `sweep_mcp_tokens`; `docs/headless_mcp_plan.md`).

`phone_origin.rs` (#2348): rules a phone made (`phone_device`, stamped by `headless` and via the window requests' `device_id`) are cancelled once that phone is unpaired or no longer reaches the scope (`discovery::ScopeAccess`, the catalog's own rule) — swept after admin revoke/forget-all, at scheduler start and by the window's access commands, and re-checked in every claim.

`web_client.rs` (hosted plan §3.5, §10 P2): the browser desktop client's transport — `/desktop/*` serves the web bundle from disk (`<ENV>WEB_DIST` → the dev checkout's `web-dist/` → `<control_dir>/web-dist`), `/desktop/login?exp=&n=&sig=` (a sign-in link = HMAC of the `0600` token file `web-client.token` over an expiry + nonce, one login each within `LOGIN_LINK_TTL`; `rotate_login_token` retires them all; its own cookie `DESKTOP_SESSION_COOKIE`, lockout after ten failures; `/desktop/logout` and the `desktop_logout` call end a session) and `/api/v1/desktop/ws`: text frames `call`/`ret`, `sub`/`unsub`/`event`, `emit`; binary `[kind][u32 id][payload]` for `write_file_bytes` in and `read_file_bytes` out; `WebEvents` is the core's `EventSink` (per-client bounded queue, events shed when full, answers never); every call runs through `core_dispatch` as `Caller::Client(web-n)` with the SESSION's `Role` (the token login is `Admin` and exists on the desktop only — behind the gateway `/desktop/login` is a 404 and only the device session counts; a gateway-verified account's role is fixed at login, never read from a frame) — the transport's own commands pass the class check too (`transport_refusal`), and a user's path arguments (`core_dispatch`'s table), tickets and grants are held to their roots (`core_dispatch::user_path`) where an admin keeps OS-dialog parity; a reconnect with `?resume=<id>` inside `RESUME_GRACE` keeps the id (= the terminal router's view key and the registry's PTY owner), otherwise its PTYs are released (`PtyRegistry::release_client`); `desktop_file_ticket` mints a ticket for the user-content origin (`/content/{ticket}` on the next port, `CSP: sandbox`, active types as attachments). Every route refuses a non-loopback `Host`; the socket also an inexact `Origin`. Off unless `MobileHostSettings.browser_client`. Behind the gateway (`ServerLink`, set by `host::run_with(Listen::Unix)`): `Host` must be the gateway's public host, the socket's `Origin` `https://` + it, the phone store's device-key session cookie signs the browser in too (`SessionRef::Device`; role = the gateway's `x-gateway-role`), tickets name the user-content origin or are refused when there is none, the CSP says `wss:`. The `assistant` scope (`ScopeKind::Assistant`, `discovery::assistant_open` = flag and `assistant_access`): opaque CLI/model launches (`assistant.rs`), `headless::create_chat`/`launch_options` arm, folder-shaped routes answer `404 not_a_project` (`host.rs` `has_folder`/`no_schedules_here`), `POST /projects/{id}/activate?tab=` starts one restored chat.
