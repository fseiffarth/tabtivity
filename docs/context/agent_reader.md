# Desktop Reader — module notes (`TerminalReaderView.tsx`, `lib/agents/agentReader.ts`)

Detail of the desktop's chat Reader over an agent pane, the phone Focus
Reader's twin. Session records and turn state: `agent_sessions.md`. The file
map keeps one line for the view.

Moved verbatim from the file map on 2026-10-19; verify against the code.

Optional desktop Reader over a Claude/Codex/OpenCode pane (prompt strip's Chat/Terminal switch: the agent conversation as a chat; the strip is docked under the pane in both modes, switches flush right, so the switch never moves — over the chat it drops the last prompt, which the chat pins itself, and the chat reaches down over its row: the composer is that row — a one-line box growing upward, Send an icon in its corner — with the switches right of it, where they stand in terminal mode): the phone's Focus Reader — `agent_tab_transcript` read while shown on its transcript watch (`lib/agents/transcriptWatch.ts` `watchedReads`: `transcript-changed` + 15 s backstop, 2 s when unwatched), `mobile-web` `transcriptTurns`/`answerHtml`/`chatTimes` — portaled over the still-running xterm; composer sends via `sendSteeringPrompt`, and every prompt it sends (steering's prompt box too) shows as sending at once via `lib/agents/sentPrompts.ts`, kept while the agent works — in that module, not the Reader, so a queued prompt survives the Reader being unmounted (Terminal view) and is never let go while the pane is hidden. On Claude, ↑ in the empty composer while the CLI's box reads `Press up to edit queued messages` takes the queue back (`mobile-web/src/terminal/queuePull.ts`, probed on 2.1.303: ↑ moves every queued message into the box and out of the queue, Ctrl+U deletes to the line start or the break before it; Ctrl+L does not clear): the text goes into the composer, the bubbles of the newest sent prompts the box ends with are dropped, and Claude's box is emptied and read back. `lib/agents/readerLive.ts` reads the pane's xterm buffer with the phone's parsers (`readSelectPrompt`, `agentWork`): a waiting dialog becomes answer buttons (arrow keys + Enter; ↑/↓ from the empty composer walk them) — a several-question one gets ←/→ steps (Claude ←/→, Codex PageUp/PageDown, Gemini/Qwen Tab/Shift+Tab; Gemini's Review page read as a one-row Submit dialog, `readReviewStep`) to change an answer before Submit — a busy row gets Stop (Esc). One choice per agent CLI, shared live by all its panes and remembered (localStorage), terminal by default.

`TerminalReaderStatus.tsx` + `lib/agents/codexStatus.ts`: Codex Status button or `/status` in the chat composer opens remaining context and usage meters, reset times and the native card's details; an explicit idle request uses the existing command path, a busy view uses rollout figures, missing readings stay absent and raw output remains expandable. Claude gets the same panel: its `/status` is the Settings dialog drawn over the composer, so `readClaudeStatus` takes the Status page (tab row down to `Esc to cancel`) and the panel closes the dialog with one Esc per request once it has read it; its meters come from the transcript usage figures.

`TerminalReaderContext.tsx` + `lib/agents/contextUsage.ts`: the Context button beside Status, or `/context` in the composer (Claude), opens the same box with the session's `/context` card drawn as a stacked bar of the window (free space the track, the autocompact buffer hatched at its end), a legend and the card's listings (MCP tools, custom agents, memory files, skills) folded with per-item bars. `/context` prints into the scrollback rather than a dialog, so nothing is dismissed; the card is read off the last 400 rows. Copilot CLI prints the same kind of card (`readContextUsage` reads both, tested) but has no Chat view; Codex (context only inside `/status`), OpenCode and Gemini have no `/context`.

`TerminalReaderFacts.tsx`: the phone's facts row over the composer — model (click → the session's `/model` picker as a list, `readModelPicker`), effort (the busy row's or the transcript's `effort`; click → Claude's `/effort` levels as a list, elsewhere the `/model` picker), mode (Codex's own `/permissions` picker with confirmation steps; elsewhere the phone's `agentModes` list, walked with Shift+Tab), folder + worktree, branch (on a local project's resumable agent a chip: the project folder and its linked worktrees as a list, a pick stops the CLI, moves its conversation where the CLI allows — `services::agent_relocate` — and respawns the tab there, `moveAgentToWorktree` → `switchAgentWorktree`; the phone's ⎇ chip runs the same move through the bridge's `tab_worktrees`/`move_worktree`, flagged per tab by the catalog's `worktree_movable`, its rows worded by the shared `worktreeChoiceText`), context, 5h/week limits (`agent_usage`). While a session picker is up (`useSessionPicker` → `holdSessionPicker`) the tab takes no message: its registered input reads not ready, `sendSteeringPrompt`/`submitScheduledAgentMessage` throw `SessionPickerOpenError` and the composer says so — a prompt typed then lands in the CLI's picker and is lost. ↑/↓ in the composer walk the session's prompts (`composerHistory`). A `/` opens `ReaderSlashMenu.tsx`, the phone composer's command menu (`mobile-web` `slashCommands.ts`: the CLI's commands, ones sent before first; picking only fills the box). Unsent composer text is kept per tab across tab switches and the switch (`lib/agents/readerDrafts.ts`, memory only). A subagent card opens its own conversation (`readerRequest`'s `subagent`), with the phone's navigation (`mobile-web` `terminal/subagents.ts`): back-up bar, ‹ n of m › siblings, a Subagents list (a Claude `Workflow` call is one such card: it opens the run's agents, grouped by phase as their kind, each opening as a subagent; nothing typed in a workflow or its agents reaches them — it goes to the session); on a Claude tab the composer then writes to that subagent through Claude's own agent list (`mobile-web` `terminal/subagentInput.ts`, shared with the phone: ↓ to the list or `/tasks`, its row viewed and checked by the label over the box, the words typed, back to main). Under the working row, a line per shell Claude is running (`AgentTranscript.shells`, stripped from the phone API: `Bash` calls without a result, and background ones until a task notification ends them or no process holds their output file open — `/proc`, Linux); a click shows the whole command. A screen the live reading cannot place (`ReaderLive.stray`: no dialog, busy row or input box) for `STRAY_MS` gets a row with Go to terminal (switches the CLI's choice off). The same row, worded for it, follows a sent prompt let go after `PENDING_MS` that the stored conversation never recorded (a store the Reader misreads — OpenCode 2's message kind sat in a column it did not read): the turn is only in the terminal; the row stays until the conversation gains a turn.

Resume menu (`TerminalReaderChats.tsx`, `lib/agents/agentChats.ts`, backend `services::agent_chats`): a Resume ▴ button beside Diffs on the prompt strip (not "Chats": beside the Chat/Terminal switch that read as the same control), for Claude, Codex, OpenCode and Antigravity tabs running on this machine. It lists the earlier conversations the CLI keeps for the tab's folder, newest first, each by its first prompt with its last under it; the filter narrows the rows read so far and older ones come a page at a time (a page reads at most 200 session files — a Claude folder can hold over a thousand, most of them never prompted). A pick shows the chat read-only in the Reader — `agent_tab_transcript`/`agent_tab_changes` with `chat`, its subagents openable — under a bar (back, ‹ n of m ›, Resume) and a footer where the composer stands; no live screen reading is drawn under it, since none of it belongs to that chat. OpenCode's and Antigravity's chats come from their SQLite stores by folder (`opencode_store::folder_chats`, `google_chat::antigravity_chats`: top-level sessions / main conversations, each by its first prompt); a picked OpenCode chat reads with its subagents and Diffs, an Antigravity one without (its store carries no diffs Tabtivity reads). Resume reuses Undo clear's two ways (`agent_session::resume_chat_plan`): Claude gets `/resume <id>` typed; Codex has its record pointed at the chat (source `resume`) and is relaunched; OpenCode has its plugin's record pointed at it and is relaunched, the spawn turning that into `--session <id>` (`opencode_session::resolve`); Antigravity, which has no hook, gets the chat written into the tab's live-session record and is relaunched, the spawn turning `--continue` into `--conversation <id>` (`google_chat::resolve`) — the Reader and later restarts follow that conversation until the tab begins one after the record was written (a `/new`), then the newest again. Disabled while the agent works: a relaunch would end the turn. Every id the renderer names is looked up again inside the folder's own chats (`agent_chats::chat_file`) before it is read or resumed.
