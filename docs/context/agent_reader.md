# Desktop Reader — module notes (`TerminalReaderView.tsx`, `lib/agents/agentReader.ts`)

Detail of the desktop's chat Reader over an agent pane, the phone Focus
Reader's twin. Session records and turn state: `agent_sessions.md`. The file
map keeps one line for the view.

Moved verbatim from the file map on 2026-10-19; verify against the code.

Optional desktop Reader over a Claude/Codex/OpenCode pane (prompt strip's Chat/Terminal switch: the agent conversation as a chat): the phone's Focus Reader — `agent_tab_transcript` read while shown on its transcript watch (`lib/agents/transcriptWatch.ts` `watchedReads`: `transcript-changed` + 15 s backstop, 2 s when unwatched), `mobile-web` `transcriptTurns`/`answerHtml`/`chatTimes` — portaled over the still-running xterm; composer sends via `sendSteeringPrompt`, and every prompt it sends (steering's prompt box too) shows as sending at once via `lib/agents/sentPrompts.ts`, kept while the agent works. On Claude, ↑ in the empty composer while the CLI's box reads `Press up to edit queued messages` takes the queue back (`mobile-web/src/terminal/queuePull.ts`, probed on 2.1.303: ↑ moves every queued message into the box and out of the queue, Ctrl+U deletes to the line start or the break before it; Ctrl+L does not clear): the text goes into the composer, the bubbles of the newest sent prompts the box ends with are dropped, and Claude's box is emptied and read back. `lib/agents/readerLive.ts` reads the pane's xterm buffer with the phone's parsers (`readSelectPrompt`, `agentWork`): a waiting dialog becomes answer buttons (arrow keys + Enter; ↑/↓ from the empty composer walk them) — a several-question one gets ←/→ steps (Claude ←/→, Codex PageUp/PageDown, Gemini/Qwen Tab/Shift+Tab; Gemini's Review page read as a one-row Submit dialog, `readReviewStep`) to change an answer before Submit — a busy row gets Stop (Esc). One choice per agent CLI, shared live by all its panes and remembered (localStorage), terminal by default.

`TerminalReaderStatus.tsx` + `lib/agents/codexStatus.ts`: Codex Status button or `/status` in the chat composer opens remaining context and usage meters, reset times and the native card's details; an explicit idle request uses the existing command path, a busy view uses rollout figures, missing readings stay absent and raw output remains expandable. Claude gets the same panel: its `/status` is the Settings dialog drawn over the composer, so `readClaudeStatus` takes the Status page (tab row down to `Esc to cancel`) and the panel closes the dialog with one Esc per request once it has read it; its meters come from the transcript usage figures.

`TerminalReaderFacts.tsx`: the phone's facts row over the composer — model (click → the session's `/model` picker as a list, `readModelPicker`), effort (the busy row's or the transcript's `effort`; click → Claude's `/effort` levels as a list, elsewhere the `/model` picker), mode (Codex's own `/permissions` picker with confirmation steps; elsewhere the phone's `agentModes` list, walked with Shift+Tab), folder + worktree, branch, context, 5h/week limits (`agent_usage`). ↑/↓ in the composer walk the session's prompts (`composerHistory`). A `/` opens `ReaderSlashMenu.tsx`, the phone composer's command menu (`mobile-web` `slashCommands.ts`: the CLI's commands, ones sent before first; picking only fills the box). Unsent composer text is kept per tab across tab switches and the switch (`lib/agents/readerDrafts.ts`, memory only). A subagent card opens its own conversation (`readerRequest`'s `subagent`), with the phone's navigation (`mobile-web` `terminal/subagents.ts`): back-up bar, ‹ n of m › siblings, a Subagents list (a Claude `Workflow` call is one such card: it opens the run's agents, grouped by phase as their kind, each opening as a subagent; nothing typed in a workflow or its agents reaches them — it goes to the session); on a Claude tab the composer then writes to that subagent through Claude's own agent list (`mobile-web` `terminal/subagentInput.ts`, shared with the phone: ↓ to the list or `/tasks`, its row viewed and checked by the label over the box, the words typed, back to main). Under the working row, a line per shell Claude is running (`AgentTranscript.shells`, stripped from the phone API: `Bash` calls without a result, and background ones until a task notification ends them or no process holds their output file open — `/proc`, Linux); a click shows the whole command. A screen the live reading cannot place (`ReaderLive.stray`: no dialog, busy row or input box) for `STRAY_MS` gets a row with Go to terminal (switches the CLI's choice off).

Resume menu (`TerminalReaderChats.tsx`, `lib/agents/agentChats.ts`, backend `services::agent_chats`): a Resume ▾ button beside Diffs on the prompt strip (not "Chats": beside the Chat/Terminal switch that read as the same control), for Claude and Codex tabs running on this machine (the two CLIs found and resumed by id). It lists the earlier conversations the CLI keeps for the tab's folder, newest first, each by its first prompt with its last under it; the filter narrows the rows read so far and older ones come a page at a time (a page reads at most 200 session files — a Claude folder can hold over a thousand, most of them never prompted). A pick shows the chat read-only in the Reader — `agent_tab_transcript`/`agent_tab_changes` with `chat`, its subagents openable — under a bar (back, ‹ n of m ›, Resume) and a footer where the composer stands; no live screen reading is drawn under it, since none of it belongs to that chat. Resume reuses Undo clear's two ways (`agent_session::resume_chat_plan`): Claude gets `/resume <id>` typed, Codex has its record pointed at the chat (source `resume`) and is relaunched. Disabled while the agent works: a relaunch would end the turn. Every id the renderer names is looked up again inside the folder's own chats (`agent_chats::chat_file`) before it is read or resumed.
