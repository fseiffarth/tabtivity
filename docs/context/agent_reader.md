# Desktop Reader — module notes (`TerminalReaderView.tsx`, `lib/agents/agentReader.ts`)

Detail of the desktop's chat Reader over an agent pane, the phone Focus
Reader's twin. Session records and turn state: `agent_sessions.md`. The file
map keeps one line for the view.

Moved verbatim from the file map on 2026-10-19; verify against the code.

Optional desktop Reader over a Claude/Codex/OpenCode pane (prompt strip's Chat/Terminal switch: the agent conversation as a chat): the phone's Focus Reader — `agent_tab_transcript` read while shown on its transcript watch (`lib/agents/transcriptWatch.ts` `watchedReads`: `transcript-changed` + 15 s backstop, 2 s when unwatched), `mobile-web` `transcriptTurns`/`answerHtml`/`chatTimes` — portaled over the still-running xterm; composer sends via `sendSteeringPrompt`, and every prompt it sends (steering's prompt box too) shows as sending at once via `lib/agents/sentPrompts.ts`, kept while the agent works. `lib/agents/readerLive.ts` reads the pane's xterm buffer with the phone's parsers (`readSelectPrompt`, `agentWork`): a waiting dialog becomes answer buttons (arrow keys + Enter; ↑/↓ from the empty composer walk them) — a several-question one gets ←/→ steps (Claude ←/→, Codex PageUp/PageDown, Gemini/Qwen Tab/Shift+Tab; Gemini's Review page read as a one-row Submit dialog, `readReviewStep`) to change an answer before Submit — a busy row gets Stop (Esc). One choice per agent CLI, shared live by all its panes and remembered (localStorage), terminal by default.

`TerminalReaderStatus.tsx` + `lib/agents/codexStatus.ts`: Codex Status button or `/status` in the chat composer opens remaining context and usage meters, reset times and the native card's details; an explicit idle request uses the existing command path, a busy view uses rollout figures, missing readings stay absent and raw output remains expandable.

`TerminalReaderFacts.tsx`: the phone's facts row over the composer — model (click → the session's `/model` picker as a list, `readModelPicker`), effort (the busy row's or the transcript's `effort`; click → Claude's `/effort` levels as a list, elsewhere the `/model` picker), mode (Codex's own `/permissions` picker with confirmation steps; elsewhere the phone's `agentModes` list, walked with Shift+Tab), folder + worktree, branch, context, 5h/week limits (`agent_usage`). ↑/↓ in the composer walk the session's prompts (`composerHistory`). A `/` opens `ReaderSlashMenu.tsx`, the phone composer's command menu (`mobile-web` `slashCommands.ts`: the CLI's commands, ones sent before first; picking only fills the box). Unsent composer text is kept per tab across tab switches and the switch (`lib/agents/readerDrafts.ts`, memory only). A subagent card opens its own conversation (`readerRequest`'s `subagent`), with the phone's navigation (`mobile-web` `terminal/subagents.ts`): back-up bar, ‹ n of m › siblings, a Subagents list; on a Claude tab the composer then writes to that subagent through Claude's own agent list (`mobile-web` `terminal/subagentInput.ts`, shared with the phone: ↓ to the list or `/tasks`, its row viewed and checked by the label over the box, the words typed, back to main). Under the working row, a line per shell Claude is running (`AgentTranscript.shells`, stripped from the phone API: `Bash` calls without a result, and background ones until a task notification ends them or no process holds their output file open — `/proc`, Linux); a click shows the whole command. A screen the live reading cannot place (`ReaderLive.stray`: no dialog, busy row or input box) for `STRAY_MS` gets a row with Go to terminal (switches the CLI's choice off).
