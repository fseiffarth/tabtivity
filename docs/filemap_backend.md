# Tabtivity — Backend File Map (`src-tauri/src/`)

See the root `AGENTS.md` for project rules; `docs/filemap_frontend.md` is the
frontend file map.

Deliberately **not** a `CLAUDE.md` (agents auto-load those). Grep it for the
file you touch. **One line per row**: what the file is for, plus an invariant
only when breaking it does damage. The *why* goes in code comments or
`docs/context/`, never here. A row past ~600 characters moves its detail to a
`docs/context/` file and keeps a pointer. Pre-2026-09-18 long-form rows: `docs/filemap_rationale/backend.md`.

**Top level**

| File | Purpose |
|------|---------|
| `main.rs` | Tauri app entry point, plugin registration. |
| `lib.rs` | Command registration (`generate_handler!`), app setup, hook/restore install; crash logger (panic hook + async-signal-safe fatal-signal handler that restores `SIG_DFL` and re-raises; headers carry `commit=` so `scripts/crash-symbolize.sh` can use the build `scripts/retain-dev-build.sh` kept); per-window renderer reload budget; macOS menu bar (`macos_menu_plan`). |
| `storage.rs` | JSON persistence helpers: unique-temp atomic replacement (staged file fsync → rename → parent-directory fsync, #172, observed by tests through the `durability` seam) and serialized, corruption-preserving read-modify-write transactions. `FileLock`: the advisory sibling-`.lock` guard that serialises a second Tabtivity process; `patch_json` holds it across its read-modify-write. `FileLock::exclusive`/`shared` fail on any lock error; `*_or_unlocked` is the explicit lockless fallback (`lock_unsupported`), only for callers with a revision/CAS check. `projects_path`/`settings_path`/`load_settings` name the two registry files. `ASSISTANT_SCOPE` + `is_reserved_scope(id)`: the one funnel for the reserved scope ids (root, assistant; trims, `project_key`, case-insensitive). `iso_now` (chrono, `+00:00`, the form persisted files carry); `patch_private_json` (owner-only); `read_tree_json{,_text}` / `write_json_in` for project-tree files (no-follow, FIFO-safe, 64 MB cap). |
| `paths.rs` | Canonical Tabtivity directory paths; effective `PATH`; trusted helpers (`helper_program`/`system_executable`: root-owned Unix dirs, or on Windows Program Files\Git/System32 copies `private_file::admin_locked` accepts). |
| `clock.rs` | The one wall-clock reading: `now_secs`/`now_ms` (u64, 0 before 1970) and `unix_secs(SystemTime)`; callers cast where they store i64. |
| `quote.rs` | The one shell-quoting rule per shell: `posix` (`'…'`, `'` → `'\''`) and `powershell` (`'…'`, `'` doubled). `ssh_exec::shell_quote` is `posix` under its old name. |
| `digest.rs` | `hex(&[u8])` (lowercase) and `sha256_hex(&[u8])` — the one copy of each. |
| `sysstat.rs` | Per-process CPU via `/proc` (`descendant_pids`), whole-system `SystemSnapshot`, and `machine_load()` — aggregate-only, no process table (cheap enough to poll). `process_start(pid)`: the platform's process start time (pid identity across reuse, for subtree reaping). Unsupported target answers `supported: false`, never zeros. |
| `gpustat.rs` | Whole-device GPU memory as two pools (dedicated VRAM + shared/GTT; callers sum) plus sensors, from DRM sysfs or `nvidia-smi`; ~1 s cache. Missing readings are `None`, never 0. Per-process GPU is separate (monitor only). Remote hosts parsed by the same parsers. |
| `tauri_host.rs` | The desktop app as a host of `app_core` (hosted plan §3.2): `TauriEvents` (Tauri's `emit_str`/`emit_str_to` as the core's `EventSink`; a client id is a window label), `install` (builds the system `CoreCtx` from `lib.rs`'s `core_state`, manages it, points `app_core::rt` at Tauri's runtime), `system_ctx(&app)`, and `Ctx` — the `CommandArg` newtype a converted command takes in place of `AppHandle`/`State`/`Window`; its caller is the CALLING webview's label, never payload data. `CONVERTED_COMMAND_FILES` lists the `commands/*.rs` files whose bodies are Tauri-free (the attribute aside); a test holds them to it. The one module that knows a client is a window. |
| `test_util.rs` | Tests only (`#[cfg(test)]`): `wait_until(within, cond)` bounded polls with `PATIENCE`, and `tempdir_via_symlink()` for code that compares a path against one the OS reports back (FSEvents, `/proc/<pid>/fd`) — use them instead of fixed sleeps and plain tempdirs. Shared git fixtures `git`/`git_output`/`init_repo` (foreign `GIT_*` and global config cleared). |
| `../patches/tauri-runtime-wry/` | Vendored tauri-runtime-wry 2.12.1 via root `[patch.crates-io]`; one `TABTIVITY PATCH` (`Context.main_thread` behind an `Arc`) stops off-thread `AppHandle` clones racing tao's Linux `Rc` — re-apply on every tauri bump. |
| `../tests/it.rs` | The one integration-test binary (`autotests = false`; `[[test]]` rows in `Cargo.toml`): `#[path]` mods over the other `tests/*.rs`, so they link the lib once, not per file. `server_secrets.rs` stays its own `[[test]]` (built `--no-default-features` for the daemon). Process env is shared: state-dir tests use `it.rs`'s `isolated_state_dir()`; `projects_commands.rs` (rewrites `HOME`) is a second binary. |
| `../../scripts/gates.sh` | AGENTS.md's gates, only those the change (diff vs HEAD + untracked, or `--base`) touches; `--all` runs every one. Area detection shared with `ci-local.sh --fast` via `scripts/lib/changed.sh`. Both re-exec themselves on SCHED_IDLE + nice 19 (`scripts/lib/low_priority.sh`; `GATES_FULL_PRIORITY=1` skips) so a gate run never lags the window. |
| `../../scripts/codeql_reviewed.py` + `../../.github/codeql/` | CodeQL false-positive reviews: exact rule, file, line and whole-file SHA-256; any edit expires a review. Filters between analysis and upload, preserves removed results with reasons in a runner audit JSON; `test_codeql_reviewed.py` verifies that unreviewed findings survive. |
| `../../scripts/package-server-deb.sh` | Builds the server's `.deb` (`<slug>-server_<ver>_<arch>.deb`: serverd, gateway, admin helper into `/usr/lib/<slug>/`, `web-dist`/`mobile-dist` into `/usr/share/<slug>/`); Depends' glibc read off the binaries; postinst try-restarts the server units on upgrade, prerm stops them on remove, tmux@ never touched. Units/accounts stay `admin-helper install`'s. ci-cd.yml's `package-server` job → release.yml; `app_update::is_server_package` keeps it out of desktop updates. |
| `../../scripts/fresh-vm.sh` | Fresh Ubuntu GNOME desktop for release testing, baked once with cloud-init and opened on a qcow2 overlay; desktop package repair and explicit GDM registration on each package disc (preserves conffiles, defers package service starts), bake/desktop share VGA/NIC layout, guest login `tester` / `tester`, boot output in `serial.log`. Host desktop entry runs its installed script copy; QEMU guest agent starts the app in an existing VM and runs `repair` from the host to fix packages/start GDM without resetting the guest; an unavailable agent directs the user to package-disc repair on the next boot. Guest-script regression tests: `scripts/test_fresh_vm.py`. |
| `../../scripts/server-vm.sh` | A headless test server in plain QEMU (never libvirt): `<small\|medium\|large> [--disk ≤500] [latest\|<ver>\|file.deb\|--build]` bakes an Ubuntu cloud base once (Tailscale, `ops` + its own SSH key, host loopback port), overlays a sparse disk that only grows, installs the server `.deb` (release ones checked against the signed `SHA256SUMS`) and runs guide steps 4–7 inside over SSH, each step marked done in `/var/lib/server-vm`. `start`/`stop`/`ssh`/`invite`/`status`/`reset`. The VM is found by its pid file, never `pgrep -f`. Sibling of `fresh-vm.sh`. |

**Core crate (`../../src-core/`, package `app-core`, lib `app_core`)** — the Tauri-free core of the hosted plan (§3.2); nothing in it may name `tauri`. Both hosts build its `CoreState` and implement its `EventSink`.

| File | Purpose |
|------|---------|
| `src/lib.rs` | Module list and re-exports; the crate's doc says what has moved so far. |
| `src/brand.rs` | The app's name: the one backend place it is spelled. Display/slug/upper forms, literal macros for `concat!` (`app_name!`, `app_slug!`, `app_env!`, `app_tab_command!`), and every name the app persists or puts on the wire as a current constant plus its `LEGACY_*` twin (old brand). `src-tauri/build.rs` includes it by path. Twin of `src/lib/brand.ts`. The dev scripts read the same names through the sourced `scripts/lib/brand.sh` (parses this file and `src-tauri/Cargo.toml`'s `[[bin]]`; a test here sources it and compares). |
| `src/services/mod.rs` | The services already moved (`agent_usage`, `big_folders`, `fence_scope`, `git_guard`, `remote_agents`, `schedule_usage`, `text_completion`, `vm_proxy`, `web_safety`, `webkit_a11y`); their rows stay in the services table below. The desktop's `services/mod.rs` re-exports each, so `crate::services::…` keeps resolving there. A module moves once nothing it reaches is still in `src-tauri`. |
| `src/sync.rs` | `LockExt::lock_ok()` on `std::sync::Mutex`: locks, recovering a poisoned guard. The one way to take a plain-data lock (no `lock().unwrap()`, no per-file `fn lock`); the mail store's error mapping is the deliberate exception. Gateway can't link it and keeps `PoisonError::into_inner`. |
| `src/ctx.rs` | `CoreCtx { state, events, caller }` — what a command body or service gets instead of Tauri. `CoreState`: the managed singletons keyed by type (`manage` builder, `get` panics like Tauri's `State`; a host hands Tauri and the core clones of ONE `Arc`, never two values). `EventSink`: `emit_json`/`emit_json_to(ClientId)` take one pre-serialized payload; `emit`/`emit_to` on `dyn EventSink` serialize once. `Caller::{System, Local, Client}`; `ClientId` (desktop: the window label, `MAIN`). `NullEvents`, `RecordingEvents` for tests. |
| `src/rt.rs` | The runtime seam: `spawn`/`spawn_blocking`/`block_on` on the handle the host `install`ed, else the current runtime, else a lazily built fallback (Tauri's `async_runtime` semantics, so the §3.2 swap is mechanical). `blocking`/`try_blocking(label, f)`: what an async command awaits for blocking work — a join failure becomes `"<label> task failed: …"`. |

**Gateway crate (`../../src-gateway/`, package `app-gateway`, lib `app_gateway`)** — the hosted server's gateway and admin helper (plan §3.1, §4, §8; `docs/context/server_gateway.md`). Links no core service: `brand.rs` and the sidecar's accept-side `limits.rs` (connection cap, handshake/body/idle deadlines) are compiled in by path. Linux only at run time; builds everywhere.

|------|---------|

| `src/policy.rs` | The server-wide policy file (admin feature switches for mail/calendar/todo/sharing, the Ollama allowlist): missing → defaults, corrupt → the daemon fails closed. Also compiled into the daemon by `#[path]`. |
| `src/server.rs` (+ `server/tests.rs`) | The gateway's HTTP surface: pair by code prefix, challenge/session by device owner, the routing cookie, every other request to the caller's own daemon (WebSocket splices registered so a revocation aborts them), PWA statics before sign-in, `/gateway/v1/{audit,policy,status}` (status looks at each socket, never connects: a connect starts a daemon), the content listener; both listeners behind `limits::GuardedListener`; a role change closes the account's live sockets. Tests run it against fake daemons on real unix sockets. |
| `src/rate.rs` | The gateway's rate limits (P3 review finding 12): strangers — unknown accounts, accounts with no invite pending and no recent use, unknown device ids — counted per source and in their own shared window; known devices per device, per account and under a separate ceiling; the source is the rightmost `X-Forwarded-For` of a loopback peer (Tailscale Serve's). |
| `src/sudoers.rs` | Does sudo grant an account anything? `/etc/sudoers` and its includes parsed read-only under a root dir (tests use fixtures); any user list naming the account, its groups, uid, an alias, `ALL` or a netgroup counts; unreadable files or a non-`files` nsswitch source fail closed. The helper refuses such accounts (finding 11). |
| `src/broker.rs` (+ `broker/tests.rs`) | The key broker (plan §5.4, P5): `<slug>-gateway broker` as `<slug>-auth` on `127.0.0.1:8739` (systemd-held port); a per-user broker token (the keeper's `tokens.json`) swapped for the key, only `messages`/`count_tokens`/`models` forwarded, `Origin` refused, monthly budgets (`meta.json`) enforced, usage metered from the provider's answers (`Meter`, SSE or JSON) into `<cli>/usage/<user>.json`; tests against a fake provider. |
| `src/keeper.rs` / `src/keys_wire.rs` | The key keeper (plan §5.4, P3b): the admin's agent API keys at `/var/lib/<slug>-auth/<cli>/api-key` (0600, `<slug>-auth`), answered on `/run/<slug>/auth.sock` by caller uid only (`Peers`: the gateway's account sets/removes/lists and sets each key's user list, never reads; a server user — `helper::check_account` — lists and fetches only keys whose list names it, and asks for fingerprints of current and earlier keys; others refused; 4 connections per uid, 2 s each), audit rows without the key, `ask` (the gateway's client). **Daemon crate (`../../src-serverd/`, package `app-serverd`, bin `<slug>-serverd`)** — a one-line `main` over `app_lib` built with `default-features = false`: the library without its `desktop` feature (Tauri, WebKitGTK/GTK, xcb, arboard, the OS keyring), so the daemon links libc/libm/libgcc_s only. Build it alone (`cargo build -p app-serverd`), or Cargo unifies the desktop's features into it. In the library, `desktop` gates the window/OS command modules (`commands/mod.rs`), Tauri-typed commands, `lib.rs`'s window host and the keyring code; command attributes are `#[cfg_attr(feature = "desktop", tauri::command)]`, which `build.rs`'s dispatcher generator reads (and the cfg of a gated module). |
