# Server mode — module notes (`src-tauri/src/services/server/`)

Per-file detail of the per-user daemon's half of the server version. The
gateway, admin helper and their reasons: `server_gateway.md`; status and
decisions: `docs/server.md`. The file map keeps one line for the folder.

Moved verbatim from the file map on 2026-10-19; verify against the code.

Server mode (hosted plan §3.1, §10 P3): `mod.rs` — `is_server()` (`<PREFIX>SERVER_MODE=1`, read once), `ServerConfig::from_env` (the unit's `SERVER_SOCKET`, `SERVER_GATEWAY_UID`, `SERVER_ORIGIN`, `SERVER_CONTENT_ORIGIN`), `tmux_socket()` (`tmux -L <slug>` in server mode, `<PREFIX>TMUX_SOCKET` override; `tmux_local::tmux_command`/`socket_args` apply it everywhere), `cli_root()` (the admin-owned `/opt/<slug>/agents`, §5.1), the gateway's trusted routing headers (`x-gateway-user/role/device`; `gateway_role` fails closed to a user and is nobody's word outside server mode).

`daemon.rs` — `tabtivity-serverd` (`src-serverd/`, also `tabtivity --serverd`): its own state dir and app home first (`server_dirs`: `~/.local/share/<slug>-server`, `~/<slug>-server`, apart from a desktop app of the same account), `PR_SET_DUMPABLE=0`, the vault installed (`install_vault`, kernel keyring), the sidecar's `HostConfig` from the gateway origin (Mobile + browser client on, `settings.json` not consulted), `host::run_with(…, Listen::Unix)` (adopts the socket-activation fd 3 when systemd passed one, `activation_fd`); `socket_path_for(user)` = `/run/<slug>/users/<user>.sock`; the admin helper's subcommands run as the user — `--write-invite <exp>` / `--revoke-device` (secret on stdin) — and as the CLI account, `--install-cli <id>` into the server-wide root. `mod.rs` also compiles the gateway's `wire.rs`/`policy.rs` by `#[path]`: `server_policy()` (the gateway-owned policy file, fails closed), `features_of`/`feature_on`/`feature_refusal` (admin switch ∧ the user's `Settings.disabled_features`; `core_dispatch` refuses `feature-off`, the phone routes 403, alarms pause), `content_path` (`/content/<user>/<ticket>`), `routed_pairing_code` (`user:code`).

`secrets.rs` — the §6.8 device-released key's primitives: K wrapped per device (ephemeral P-256 ECDH + HKDF + AES-256-GCM, device id as AAD), the recovery-code wrap (v2: K wrapped to the code's P-256 key so a rotation re-wraps it without the code; `A` sealed under K backs `identity_binding`/`check_repin`), `WrapFile` (`<state>/secrets/wraps.json`, 0600; `kid`, `check`, pending `rotate`), and the kernel persistent keyring (`keyring::store/load/clear`).

`vault/rotation.rs` — revoking rotates K: journal → `.next` files → atomic `wraps.json` rename (commit) → move-ins → hold; `settle` (every `Vault::new`) finishes or undoes a crashed rotation; locked → deferred to the next release; `revoke_offline`.

`vault.rs` (+ `vault/tests.rs`) — the wiring: `with_key` (mail's device mode reads/writes under the vault lock), `repin_offer` (identity re-pin with the recovery code), `action_payload` (signed set-up / new code), `KeyHold` (kernel keyring / memory), `install`/`vault()` (the daemon's only; `None` on the desktop), set-up with a one-time recovery code, ECDH enrolment checked against the pairing key, the signed unlock exchange (`start_unlock`/`finish_unlock`, HKDF vector shared with `MobileSecretsRelease.test.ts`), wraps made/dropped with devices, `subkey(K, "mail-kek" | "credentials")`, the sealed credential store `remote_credentials`/`git_credentials` use on a server, `on_unlock` (mail reopens). Tests drive the daemon end to end over a temp unix socket: invite → pair → challenge → session → `/desktop/` and the socket with the gateway's role; another uid is dropped at accept.

`agent_keys.rs` — the admin's agent API keys, the daemon's half (P3b; through `api_proxy` since #2389): the user's per-CLI choice (`agent-auth/admin-keys.json`, `choose`, which switches the CLI's own API key off), `admin_for_spawn` at every local agent spawn (fence wraps, Host session: the offer checked, the CLI named for an admin grant; no proxy in the process → fails), `for_proxy` (the key, or the broker token + loopback broker URL, for the proxy per request), `holds_admin_key` (keeper fingerprints of current and earlier keys; agent_auth never adopts a login file holding one); `daemon.rs` writes the shell tabs' shims and answers `--agent-shim` (`mark_server_process`).

`oidc.rs` — OIDC sign-in, the daemon's half (P5): the admin helper's binding (`mobile-control/oidc.json`, `--write-oidc-binding`), `check` (RS256 via `ring` / ES256 via `p256` against the issuer's JWKS, cached; `oidc_wire::check_claims`; each nonce spent once) before `host.rs`'s pair registers the key (`AuthStore::pair_verified`).

`share.rs` (+ `share/tests.rs`, against the real hub) — shared projects, the daemon's half: the hub client, the user's map `<state>/shares.json` (project → share, role, `active`/`revoked`/`deleted`, reviewed commits), push as a bundle (owner by name, editor `<user>/<branch>`, refused while agent files are unreviewed or commits carry the app's folder), `clone_into` (`--no-local --template=`), `safe.directory` pinned to the exact hub, `.git/info/exclude`, `fetch_report`, `fence_args` (tmpfs over the shared root, own hub bound back), gate 2 (`unreviewed`, `review_merge`/`merge_in`, `pending_review`/`accept_in`, `spawn_gate` in both fence and container wraps), `is_shared_dir` (git's hookless + strict-sanitize gate).

`shared_calendar.rs` (+ tests, against the real service) — shared calendars, the daemon's half: `Shared` (cache by revision, `merge_into` as `shared:<id>` calendars, `put_*`/`delete_*` routed with the record's `rev`, no move across private/shared, `wait`), `share_in`/`unshare_in` (the move, put back on refusal; the owner's stripped task links kept in `<state>/shared-calendars.json` and laid back on her card), per-viewer visibility.
