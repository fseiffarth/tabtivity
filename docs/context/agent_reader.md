# Desktop Reader — module notes (`TerminalReaderView.tsx`, `lib/agents/agentReader.ts`)

Detail of the desktop's chat Reader over an agent pane, the phone Focus
Reader's twin. Session records and turn state: `agent_sessions.md`. The file
map keeps one line for the view.

Moved verbatim from the file map on 2026-10-19; verify against the code.

Optional desktop Reader over a Claude/Codex/OpenCode/Copilot pane: readable agent panes have a top toolbar with Prompts/Resume, populated Subagents/Workspaces/Files menus — Workspaces are the session's Claude `Workflow` runs (orchestrations), Subagents the rest; git worktree moves stay the facts row's ⎇ chip — (over Chat and Diffs only: Terminal reads neither the transcript nor the live screen, so they would go stale), persistent Clear/Commit actions, and Chat / Diffs / Terminal tabs. Chat/Terminal is the per-CLI choice below; Diffs is each pane's own (`TerminalView` state), never shared or remembered, so it never takes over a CLI's other panes or a Tabby chat. The phone has the same view in its view pill (`mobile-web/src/components/ChatChanges.tsx`, `GET /api/v1/tabs/{id}/changes`, behind "Project files on the phone"). Chat has a full-width composer with Plan/Goal inside its lower edge. Diffs occupies the whole pane, with file navigation at the left and split before/after or unified rendering; closing it returns to Chat. The chat and its draft remain mounted across view switches; the underlying terminal stays running. Non-readable agents keep their prompt strip below the terminal: the phone's Focus Reader — `agent_tab_transcript` read while shown on its transcript watch (`lib/agents/transcriptWatch.ts` `watchedReads`: `transcript-changed` + 15 s backstop, 2 s when unwatched), `mobile-web` `transcriptTurns`/`answerHtml`/`chatTimes` — portaled over the still-running xterm; composer sends via `sendSteeringPrompt`, and every prompt it sends (steering's prompt box too) shows as sending at once via `lib/agents/sentPrompts.ts`, kept while the agent works — in that module, not the Reader, so a queued prompt survives the Reader being unmounted (Terminal view) and is never let go while the pane is hidden. On Claude, ↑ in the empty composer while the CLI's box reads `Press up to edit queued messages` takes the queue back (`mobile-web/src/terminal/queuePull.ts`, probed on 2.1.303, re-probed on 2.1.310, whose live box draws `❯` + a no-break space, read as a plain one: ↑ moves every queued message into the box and out of the queue, Ctrl+U deletes to the line start or the break before it; Ctrl+L does not clear): the text goes into the composer, the bubbles of the newest sent prompts the box ends with are dropped, and Claude's box is emptied and read back. Every sending bubble carries the same two moves as buttons while Claude works: **Send now** (Esc — the turn stops and Claude sends its queue at once) and **Cancel and edit** (the ↑ pull, after whatever the composer holds); the phone's Focus chat has the pair under each queued bubble, over its own copy of the screen — but its Send now asks the desktop's terminal bridge (`send_now`, `pty_bridge::queue_hint`), which presses Esc only while the pane still shows the queue hint: Claude takes a queued message into the running turn at its next tool call, and an Esc after that stops the turn that was to answer it (probed 2.1.310; Codex and Copilot take a mid-turn message in at once, OpenCode marks its queue nowhere on screen, so none of them gets the button). `lib/agents/readerLive.ts` reads the pane's xterm buffer with the phone's parsers (`readSelectPrompt`, `agentWork`): a waiting dialog becomes answer buttons (arrow keys + Enter; ↑/↓ from the empty composer walk them) — a several-question one gets ←/→ steps (Claude ←/→, Codex PageUp/PageDown, Gemini/Qwen Tab/Shift+Tab; Gemini's Review page read as a one-row Submit dialog, `readReviewStep`) to change an answer before Submit — a busy row gets Stop (Esc). One choice per agent CLI, shared live by all its panes and remembered (localStorage), terminal by default.

`TerminalReaderStatus.tsx` + `lib/agents/codexStatus.ts`: Codex Status button or `/status` in the chat composer opens remaining context and usage meters, reset times and the native card's details; an explicit idle request uses the existing command path, a busy view uses rollout figures, missing readings stay absent and raw output remains expandable. Claude gets the same panel: its `/status` is the Settings dialog drawn over the composer, so `readClaudeStatus` takes the Status page (tab row down to `Esc to cancel`) and the panel closes the dialog with one Esc per request once it has read it; its meters come from the transcript usage figures.

`TerminalReaderContext.tsx` + `lib/agents/contextUsage.ts`: the Context button beside Status, or `/context` in the composer (Claude), opens the same box with the session's `/context` card drawn as a stacked bar of the window (free space the track, the autocompact buffer hatched at its end), a legend and the card's listings (MCP tools, custom agents, memory files, skills) folded with per-item bars. `/context` prints into the scrollback rather than a dialog, so nothing is dismissed; the card is read from the transcript (`AgentTranscript.context_card`, the newest `local_command` stdout opening with `Context Usage`; stripped from the phone API, since it lists memory files by path), else off the last 400 rows — the fullscreen renderer (`"tui": "fullscreen"`) draws it in the alternate screen, which keeps no scrollback, so a card taller than the pane never showed its heading there. Copilot CLI prints the same kind of card (`readContextUsage` reads both, tested); Codex (context only inside `/status`), OpenCode and Gemini have no `/context`.

`TerminalReaderFacts.tsx`: the phone's facts row over the composer — model (click → the session's `/model` picker as a list, `readModelPicker`), effort (the busy row's or the transcript's `effort`; click → Claude's `/effort` levels as a list, elsewhere the `/model` picker), mode (Codex's own `/permissions` picker with confirmation steps; elsewhere the phone's `agentModes` list, walked with Shift+Tab), folder + worktree, branch (on a local project's resumable agent a chip: the project folder and its linked worktrees as a list, a pick stops the CLI, moves its conversation where the CLI allows — `services::agent_relocate` — and respawns the tab there, `moveAgentToWorktree` → `switchAgentWorktree`; the phone's ⎇ chip runs the same move through the bridge's `tab_worktrees`/`move_worktree`, flagged per tab by the catalog's `worktree_movable`, its rows worded by the shared `worktreeChoiceText`), context, 5h/week limits (`agent_usage`). While a session picker is up (`useSessionPicker` → `holdSessionPicker`) the tab takes no message: its registered input reads not ready, `sendSteeringPrompt`/`submitScheduledAgentMessage` throw `SessionPickerOpenError` and the composer says so — a prompt typed then lands in the CLI's picker and is lost. ↑/↓ in the composer walk the session's prompts (`composerHistory`). A `/` opens `ReaderSlashMenu.tsx`, the phone composer's command menu (`mobile-web` `slashCommands.ts`: the CLI's commands, ones sent before first; picking only fills the box). Unsent composer text is kept per tab across tab switches and the switch (`lib/agents/readerDrafts.ts`, memory only). A subagent card opens its own conversation (`readerRequest`'s `subagent`), with the phone's navigation (`mobile-web` `terminal/subagents.ts`): back-up bar, ‹ n of m › siblings, a Subagents list (a Claude `Workflow` call is one such card: it opens the run's agents, grouped by phase as their kind, each opening as a subagent; nothing typed in a workflow or its agents reaches them — it goes to the session); on a Claude tab the composer then writes to that subagent through Claude's own agent list (`mobile-web` `terminal/subagentInput.ts`, shared with the phone: ↓ to the list or `/tasks`, its row viewed and checked by the label over the box, the words typed, back to main). Under the working row, a line per shell Claude is running (`AgentTranscript.shells`, stripped from the phone API: `Bash` calls without a result, and background ones until a task notification ends them or no process holds their output file open — `/proc`, Linux); a click shows the whole command. A screen with no input box and no busy row is first read as a dialog without a footer (`readStrayDialog`, phone too): a CLI's first-run highlighted list (Claude's theme picker, `❯ ✔ Dark mode`, the tick dropped and skipped when lining rows up) or a `Press Enter to continue` screen with no highlighted row above as one Continue row; `isStrayListRow` keeps that list's `❯` from passing for Claude's input line, which always sits under a rule, and a page ending in `Press enter/esc to …` (`pressHintShown`, Codex's API-key page) never has an input box. Codex's sign-in menu puts a blank row between its numbered rows; `readSelectPrompt` bridges one blank when the next row numbers on at the same column. Captured off Claude 2.1.309, Codex 0.164.0, Antigravity 1.4.5 in a fresh home (OpenCode 2.1.3 opens straight on its input box). A screen the live reading still cannot place (`ReaderLive.stray`: no dialog, busy row or input box) for `STRAY_MS` is drawn as text (`ReaderLive.screen`, its last 40 rows) over a row with Go to terminal (switches the CLI's choice off). The same row, worded for it, follows a sent prompt let go after `PENDING_MS` that the stored conversation never recorded (a store the Reader misreads — OpenCode 2's message kind sat in a column it did not read): the turn is only in the terminal; the row stays until the conversation gains a turn.

Resume menu (`TerminalReaderChats.tsx`, `lib/agents/agentChats.ts`, backend `services::agent_chats`): a Resume ▴ button beside Diffs on the prompt strip (not "Chats": beside the Chat/Terminal switch that read as the same control), for Claude, Codex, OpenCode, Copilot and Antigravity tabs running on this machine. It lists the earlier conversations the CLI keeps for the tab's folder, newest first, each by its first prompt with its last under it; the filter narrows the rows read so far and older ones come a page at a time (a page reads at most 200 session files — a Claude folder can hold over a thousand, most of them never prompted). A pick shows the chat read-only in the Reader — `agent_tab_transcript`/`agent_tab_changes` with `chat`, its subagents openable — under a bar (back, ‹ n of m ›, Resume) and a footer where the composer stands; no live screen reading is drawn under it, since none of it belongs to that chat. OpenCode's and Antigravity's chats come from their SQLite stores by folder (`opencode_store::folder_chats`, `google_chat::antigravity_chats`: top-level sessions / main conversations, each by its first prompt); a picked OpenCode chat reads with its subagents and Diffs, an Antigravity one without (its store carries no diffs Tabtivity reads). Resume reuses Undo clear's two ways (`agent_session::resume_chat_plan`): Claude gets `/resume <id>` typed; Codex has its record pointed at the chat (source `resume`) and is relaunched; OpenCode has its plugin's record pointed at it and is relaunched, the spawn turning that into `--session <id>` (`opencode_session::resolve`); Antigravity, which has no hook, gets the chat written into the tab's live-session record and is relaunched, the spawn turning `--continue` into `--conversation <id>` (`google_chat::resolve`) — the Reader and later restarts follow that conversation until the tab begins one after the record was written (a `/new`), then the newest again. Copilot (`services::copilot_session`): a tab is spawned `--session-id <its tab uuid>` (Copilot creates or resumes that session), its chats are the folder's `session-state/<uuid>/` whose `workspace.yaml` `cwd` is the tab folder and whose `events.jsonl` holds a prompt, a pick has its record pointed at it and the tab relaunched onto `--session-id <chat>`, and the `sessionStart` hook (`agent_hint`) records the session a `/new` or in-CLI `/resume` rolls onto. Its Chat view reads `events.jsonl` (prompts, answers, `bash`/`task` cards, model, effort, context tokens) and its Diffs the `fileEdits` + `detailedContent` of `edit`/`create`/`apply_patch`; the live screen part is the generic reader plus the footer's `esc esc edit prompt` busy row. Subagents have no conversation of their own to open, the footer's model/mode are not read off the screen, and the phone's Focus view is not wired (desktop only). Disabled while the agent works: a relaunch would end the turn. Every id the renderer names is looked up again inside the folder's own chats (`agent_chats::chat_file`) before it is read or resumed.
